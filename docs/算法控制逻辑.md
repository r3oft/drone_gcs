# 算法控制逻辑

最后校准日期：2026-05-16

本文档描述当前代码中的视觉检测、视觉伺服、FSM 调度与调试 HUD。旧文档中的 `MavlinkCommander` 已不再存在；飞控控制由 `FlightBridge` 提供，MCU 动作由 `DirectSerialMCUBridge` 或 legacy `MCUBridge` 提供。

## 数据流

```text
ESP32-S3 stream/capture
  -> ZeroLatencyStreamer
  -> TargetPoseEstimator
  -> VisualServoController
  -> GlobalFSM
  -> FlightBridge / MCUBridge
```

视觉 HUD 调试流：

```text
ZeroLatencyStreamer
  -> TargetPoseEstimator.process_frame_all()
  -> per-target PD debug
  -> DebugVisualizer
```

## 目标检测

实现：`core/perception.py::TargetPoseEstimator`

当前支持两个任务类别：

| 目标 | cls_id | 使用阶段 |
|---|---:|---|
| `pickup_zone` | 0 | `TASK_REC_ALIGN` / `TASK_REC_DESCEND` |
| `delivery_zone` | 1 | `TASK_REL_ALIGN` / `TASK_REL_DESCEND` |

接口：

- `process_frame(frame, target_cls_id)`：返回单个目标类别的最高置信度 OBB。
- `process_frame_all(frame, target_cls_ids=None)`：一次 YOLO 推理中返回多个类别的最高置信度 OBB。

输出字段：

```python
{
    "cls_id": 0,
    "u": 320.0,
    "v": 240.0,
    "theta": 0.0,
    "conf": 0.92,
    "w": 64.0,
    "h": 40.0,
}
```

角度通过 `utils.geometry.normalize_obb_angle(..., symmetry_order=2)` 做 C2 对称归一化。

## 视觉伺服 PD

实现：`core/servo_controller.py::VisualServoController`

输入：

- 目标中心 `(u, v)`
- 图像中心 `(center_u, center_v)`
- OBB 角度 `theta`
- 时间间隔 `dt`

误差映射：

- 图像误差通过 `pixel_to_body_error()` 映射到机体系 x/y 误差。
- 偏航误差为 `error_yaw = -theta`。

控制律：

```text
velocity = kp * error + kd * (error - previous_error) / dt
```

特点：

- 无积分项，避免延迟和近距离抖动下的积分饱和。
- 每轴独立 deadband。
- 每轴独立 max velocity 限幅。
- `reset()` 会清空上一帧误差，状态切换后避免 D 项尖峰。

配置位置：

```yaml
servo:
  pickup_align:
    kp: { x: 0.003, y: 0.003, yaw: 0.6 }
    kd: { x: 0.001, y: 0.001, yaw: 0.1 }
    deadband: { x: 30, y: 30, yaw: 0.1 }
    max_vel: { x: 0.3, y: 0.3, yaw: 0.5 }
  delivery_align:
    ...
```

## FSM 如何使用控制量

对齐阶段：

```text
send_body_velocity(vx, vy, 0.0, vyaw)
```

下降阶段：

```text
send_body_velocity(vx * 0.5, vy * 0.5, 0.15, 0.0)
```

下降阶段优先检查飞控遥测：

- `alt < flight.land_detect_alt`
- 或 `armed == False`

满足任一条件后，进入 MCU 动作阶段。

## 丢目标策略

状态机维护 `_last_target_seen`：

- 短时无目标：保持上一次速度自然衰减。
- 超过 `fsm.target_lost_hover_s`：发送零速度悬停。
- 超过 `fsm.target_lost_climb_s`：发送 `fsm.climb_vz` 爬升搜索。

进入视觉状态时会刷新 `_last_target_seen`，避免首帧无目标误触发爬升。

## HUD 调试逻辑

入口：`scripts/run_visual_hud.py`

常用能力：

- `--target pickup_zone|delivery_zone`：选择 active control target。
- `--draw-targets all|selected`：显示全部目标或仅显示 active target。
- `--debug-targets selected|all`：显示 active target 或全部目标的误差/速度调试信息。
- active target 会在 OBB 标签中追加 `CTRL`，并使用更粗边框。
- `--record-path` 会同时输出 `with_hud/` 和 `non_hud/` 两路录像。
- `--record-segment-s` 支持分段保存，断流时可 flush 当前段。

示例：

```bash
python scripts/run_visual_hud.py \
  --target pickup_zone \
  --draw-targets all \
  --debug-targets selected \
  --record-path logs/hud_live_test/session.avi
```
