# 首次飞行调试完整流程

最后校准日期：2026-05-16

本文档按当前代码版本编写。目标是先验证软件链路，再逐步接入摄像头、MCU、飞控和实机任务。

## 0. 环境与仓库检查

推荐使用 Miniconda 环境：

```bash
cd /home/r3oft/drone_gcs
conda activate drone_gcs
python --version
python -m pytest -q
```

期望：默认单元测试通过。

注意：

- `tests/flight_tests/` 是硬件飞测脚本，不应被当作普通 pytest 单元测试自动运行。
- `weights/` 和 `datasets/` 不入库，live 视觉调试前需确认权重文件存在。

## 1. 桌面 mock 主循环

先在无硬件条件下跑通 FSM：

```bash
python main.py \
  --mode mock \
  --start \
  --mock-fast \
  --duration 2 \
  --tick-rate-hz 50 \
  --no-flight-recorder \
  --perf-print-interval 0
```

期望：

- 程序正常退出。
- 无硬件连接异常。
- FSM 能走过主要任务链路。

## 2. 摄像头与视觉 HUD

确认 ESP32-S3 CameraWebServer 可访问：

```bash
python scripts/run_visual_hud.py \
  --weights weights/cargo_obb_run2/weights/best.pt \
  --host 192.168.43.192 \
  --target pickup_zone \
  --draw-targets all \
  --debug-targets selected \
  --duration 10 \
  --record-path logs/hud_live_test/session.avi
```

检查点：

- `mode=stream` 优先；若流不可用，可 fallback 到 `capture`。
- active target 标签应包含 `CTRL`。
- pickup/delivery 同屏时，只有 `--target` 指定的类别作为控制目标。
- `record-path` 会拆成 `with_hud/` 与 `non_hud/` 两路录像。

常用参数：

```bash
--prefer-capture
--stream-preflight
--hud-corner top_right
--record-segment-s 60
--snapshot-dir logs/snapshots
```

## 3. MCU 直连串口

当前默认 MCU 链路是 PC 直连串口：

```yaml
mcu:
  transport: "direct_serial"
  port: "/dev/ttyACM0"
  baudrate: 115200
```

协议：

- PC -> MCU：`RESET\n`、`START_GRAB\n`、`START_RELEASE\n`
- MCU -> PC：`RESET_DONE\n`、`GRAB_DONE\n`、`RELEASE_DONE\n`

上线前确认：

- 串口设备名正确，例如 `/dev/ttyACM0`、`/dev/ttyUSB0`。
- 当前用户有串口权限。
- MCU 固件输出以换行结束。
- MCU 对重复命令具备可接受的幂等或安全处理。

软件单元测试：

```bash
python -m pytest tests/test_mcu_bridge.py -q
```

## 4. 飞控链路

默认 MAVLink 配置：

```yaml
mavlink:
  connection: "udp:192.168.4.1:14550"
  heartbeat_timeout_s: 5
```

飞控实测前确认：

- Pixhawk 固件和模式配置正确。
- 数传/UDP 链路可达。
- 起飞场地清空。
- 电池、电机、电调、桨叶方向检查完成。
- RC 遥控器或等效物理断电手段可用。

硬件脚本位于 `tests/flight_tests/`，需要人工明确选择运行，不能直接 `pytest tests/flight_tests`。

## 5. live 主循环启动

live 自动启动必须显式确认：

```bash
python main.py \
  --mode live \
  --start \
  --confirm-live-start \
  --conn udp:192.168.4.1:14550 \
  --mcu-port /dev/ttyACM0 \
  --duration 5 \
  --no-flight-recorder
```

建议第一次 live 只给短 `--duration`，观察：

- `RESET` 是否能连接飞控和 MCU。
- MCU 是否返回 `RESET_DONE`。
- 飞控遥测 `heartbeat_ok` 是否稳定。
- 进入 `INBOUND` 前是否符合现场安全条件。

## 6. 异常处理预期

当前 FSM 的异常策略：

- 飞控连接断开：`EMERGENCY`
- 飞控心跳丢失：`EMERGENCY`
- 任务中飞控被外部切到 RTL/LAND：`EMERGENCY`
- 起飞/降落失败：`EMERGENCY`
- MCU 命令发送失败：`EMERGENCY`
- MCU 返回失败或超时：按 `mcu.retry_max` 重试，耗尽后 `EMERGENCY`

`EMERGENCY` 首次处理会请求 `FlightMode.RTL`。
