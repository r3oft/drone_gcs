# 无人机首次飞行调试完整流程

> **目标**：从组装完成的无人机到能够安全执行起飞、悬停、降落
> 
> **硬件配置**：Pixhawk 2.4.8 + 数传模块 + 遥控器 + 电调/电机
> 
> **通信方式**：PC ←(数传)→ Pixhawk

---

## ⚠️ 安全第一原则

**在任何测试前，请牢记：**

1. **遥控器是最高优先级**：遥控器可以随时接管控制权
2. **拆桨测试优先**：所有代码逻辑测试必须先在拆桨状态下完成
3. **系留飞行**：首次带桨测试使用绳索系留
4. **紧急预案**：提前演练紧急停止操作

---

## 阶段一：地面站软件准备（Mission Planner / QGroundControl）

### 1.1 安装地面站软件

**推荐使用 Mission Planner（Windows）**

下载地址：https://ardupilot.org/planner/docs/mission-planner-installation.html

### 1.2 连接飞控

1. **USB 直连方式**（推荐用于初次校准）：
   - 使用 USB 线连接 Pixhawk 到 Windows PC
   - 打开 Mission Planner
   - 选择正确的 COM 口，波特率 115200
   - 点击 "Connect"

2. **数传连接方式**（后续代码测试使用）：
   - 数传发射端插入 Pixhawk TELEM1/TELEM2 口
   - 数传接收端插入 PC USB 口
   - 波特率设置为 57600（默认）

### 1.3 固件检查

- 确认固件版本：ArduCopter 4.x 或更高
- 如需更新固件，在 Mission Planner 的 "Initial Setup" → "Install Firmware" 中操作

---

## 阶段二：传感器校准（必须完成）

**⚠️ 警告：未校准的飞控无法稳定飞行，可能导致炸机**

### 2.1 加速度计校准（Accelerometer Calibration）

**目的**：确保飞控能正确感知水平面和重力方向

**步骤**：
1. 在 Mission Planner 中进入 "Initial Setup" → "Mandatory Hardware" → "Accel Calibration"
2. 点击 "Calibrate Accel"
3. 按照提示依次将无人机放置在以下 6 个姿态（每个姿态保持静止 5 秒）：
   - **Level**（水平放置）
   - **On its LEFT side**（左侧朝下）
   - **On its RIGHT side**（右侧朝下）
   - **Nose DOWN**（机头朝下）
   - **Nose UP**（机头朝上）
   - **On its BACK**（背面朝下）
4. 完成后会显示 "Calibration successful"

**验证**：
- 在 "Flight Data" 界面查看 HUD（抬头显示），倾斜无人机，HUD 应同步显示倾斜角度

### 2.2 罗盘校准（Compass Calibration）

**目的**：消除磁场干扰，确保航向准确

**步骤**：
1. **⚠️ 必须在室外进行**，远离金属物体、电线、建筑物
2. 在 Mission Planner 中进入 "Initial Setup" → "Mandatory Hardware" → "Compass"
3. 点击 "Start" 开始校准
4. **手持无人机**，缓慢旋转，让无人机在 3D 空间中各个方向都转一遍：
   - 水平旋转 360°
   - 机头朝上旋转 360°
   - 机头朝下旋转 360°
   - 侧翻旋转 360°
5. 进度条达到 100% 后会自动完成

**验证**：
- 在 "Flight Data" 界面查看 "heading"（航向角）
- 旋转无人机，航向角应平滑变化且与实际方向一致

### 2.3 遥控器校准（Radio Calibration）

**目的**：让飞控正确识别遥控器各通道的行程范围

**步骤**：
1. 打开遥控器，确保接收机已绑定且信号正常
2. 在 Mission Planner 中进入 "Initial Setup" → "Mandatory Hardware" → "Radio Calibration"
3. 点击 "Calibrate Radio"
4. 按照提示操作：
   - 将所有摇杆和开关移动到**最大行程**（上下左右、所有开关位置）
   - 保持 5 秒后点击 "Click when Done"
5. 检查各通道：
   - Roll（横滚）：左右摇杆左右移动
   - Pitch（俯仰）：左右摇杆上下移动
   - Throttle（油门）：左摇杆上下移动
   - Yaw（偏航）：左摇杆左右移动
   - 所有通道范围应在 **1100-1900** 之间，中位 **1500**

**验证**：
- 移动摇杆，绿色条应实时响应
- 确认油门通道在最低位时显示约 1100

### 2.4 飞行模式设置（Flight Modes）

**目的**：配置遥控器开关对应的飞行模式

**推荐配置**（使用 3 段开关）：
- **位置 1（上）**：STABILIZE（自稳模式，手动飞行）
- **位置 2（中）**：LOITER（定点悬停，GPS 辅助）
- **位置 3（下）**：**RTL（返航降落）** ← **紧急模式**

**步骤**：
1. 在 Mission Planner 中进入 "Initial Setup" → "Mandatory Hardware" → "Flight Modes"
2. 选择 "Flight Mode Channel"（通常是 Channel 5）
3. 为每个 PWM 范围分配模式
4. 点击 "Save Modes"

**⚠️ 关键安全设置**：
- 确保至少有一个开关位置设置为 **RTL** 或 **LAND**
- 测试时，遇到任何异常立即切换到 RTL/LAND

## 阶段三：电调（ESC）校准

**目的**：让所有电调识别油门信号的上下限

**⚠️ 警告：必须拆除螺旋桨！**

### 3.1 手动校准法（推荐）

**步骤**：
1. **拆除所有螺旋桨**
2. 断开电池，仅保持 USB 连接
3. 遥控器油门推到**最高**
4. 在 Mission Planner 中进入 "Initial Setup" → "Optional Hardware" → "ESC Calibration"
5. 点击 "Calibrate"，按照提示操作：
   - 连接电池
   - 听到电调发出"哔哔"声（识别最高油门）
   - 将遥控器油门拉到**最低**
   - 听到电调发出确认音（识别最低油门）
6. 断开电池，校准完成

### 3.2 验证电调校准

1. 遥控器油门最低
2. 连接电池
3. 在 Mission Planner 中解锁（或通过遥控器解锁）
4. 缓慢推油门，所有电机应**同时**启动且转速一致

## 阶段四：电机顺序与转向检查

**⚠️ 警告：仍然不要安装螺旋桨！**

### 4.1 电机编号标准（X 型四旋翼）

```
     前
      ↑
  3   ┼   1
   ╲  │  ╱
    ╲ │ ╱
  ───┼───
    ╱ │ ╲
   ╱  │  ╲
  4   ┼   2

电机 1（右前）：逆时针 ↺
电机 2（右后）：顺时针 ↻
电机 3（左前）：顺时针 ↻
电机 4（左后）：逆时针 ↺
```

### 4.2 使用 Mission Planner 测试电机

**步骤**：
1. 在 Mission Planner 中进入 "Initial Setup" → "Optional Hardware" → "Motor Test"
2. 选择 "Test motor A"（对应电机 1）
3. 设置 Throttle % 为 **5-10%**（低速测试）
4. 点击 "Test motor"
5. **验证**：
   - 确认是**右前**电机转动
   - 确认转向为**逆时针**
6. 依次测试电机 B、C、D

**如果顺序或转向错误**：
- **顺序错误**：交换飞控上对应的电调信号线
- **转向错误**：交换电调与电机之间的任意两根线

## 阶段五：飞控参数配置

### 5.1 关键参数检查

在 Mission Planner 的 "Config" → "Full Parameter List" 中检查以下参数：

| 参数名 | 推荐值 | 说明 |
|--------|--------|------|
| `FRAME_CLASS` | 1 | 四旋翼 |
| `FRAME_TYPE` | 1 | X 型 |
| `ARMING_CHECK` | 1 | 启用解锁前检查（重要！） |
| `FS_THR_ENABLE` | 1 | 启用遥控器失控保护 |
| `FS_THR_VALUE` | 975 | 失控判定阈值 |
| `FS_GCS_ENABLE` | 1 | 启用地面站失联保护 |
| `BATT_LOW_VOLT` | 10.5 | 低电压报警（3S 电池） |
| `BATT_CRT_VOLT` | 9.9 | 严重低电压（3S 电池） |

**⚠️ 失控保护（Failsafe）配置**：
- `FS_THR_ENABLE = 1`：遥控器失联时自动 RTL
- `FS_GCS_ENABLE = 1`：数传失联时自动 RTL
- 这是防止代码失控的最后一道防线

### 5.2 数传串口配置（用于 DroneKit 连接）

**如果使用 TELEM1 口**：
- `SERIAL1_PROTOCOL` = 2（MAVLink 2）
- `SERIAL1_BAUD` = 57（57600 bps）

**如果使用 TELEM2 口**：
- `SERIAL2_PROTOCOL` = 2
- `SERIAL2_BAUD` = 57

## 阶段六：WSL 环境配置与代码测试

### 6.1 WSL 串口透传

**在 Windows PowerShell（管理员）中执行**：

```powershell
# 查看可用设备
usbipd list

# 找到数传设备的 BUSID（例如 3-8）
# 绑定设备
usbipd bind --busid 3-8

# 附加到 WSL
usbipd attach --wsl --busid 3-8
```

**在 WSL 终端中验证**：

```bash
ls /dev/ttyUSB*
# 应该看到 /dev/ttyUSB0 或类似设备
```

### 6.2 安装依赖

```bash
cd /home/linux/drone/drone_gcs
```

### 6.3 连接测试（拆桨状态）

**⚠️ 确保螺旋桨已拆除！**

**如果连接失败**：

2. 检查波特率是否匹配飞控参数
3. 检查数传是否正常工作（LED 指示灯）

```bash
python tests/test_mode_switch.py --conn /dev/ttyUSB0 --baud 57600 --target GUIDED
```

**预期输出**：
```

after switch: mode=GUIDED armed=False
```

**验证**：
- Mission Planner 中应同步显示模式切换为 GUIDED

### 6.5 解锁测试（拆桨状态）

**⚠️ 再次确认螺旋桨已拆除！**

创建临时测试脚本：

```python
from core.flight_bridge import FlightBridge, FlightConfig

config = FlightConfig(connection_string="/dev/ttyUSB0", pixhawk_baud=57600)
fb = FlightBridge(config)

if fb.connect():
    print("连接成功")
    
    # 尝试解锁（不起飞）
    fb._vehicle.mode = "GUIDED"
    while fb._vehicle.mode.name != "GUIDED":
        time.sleep(0.5)
    
    print("等待飞控就绪...")
    while not fb._vehicle.is_armable:
        time.sleep(1)
    
    print("解锁电机...")
    fb._vehicle.armed = True
    while not fb._vehicle.armed:
        time.sleep(0.5)
    
    print("电机已解锁！观察电机是否旋转（应该不转，因为没有油门）")
    time.sleep(3)
    
    print("上锁电机...")
    fb._vehicle.armed = False
    
    fb._vehicle.close()
```

**预期现象**：
- 电机解锁后应该**不转动**（因为没有油门指令）
- 如果电机转动，说明油门通道有问题，**立即断电检查**

## 阶段七：首次带桨测试（系留飞行）

**⚠️ 极度危险阶段，必须严格遵守安全规程！**

### 7.1 系留装置准备

**材料**：
- 4 根细绳（尼龙绳或钓鱼线，直径 1-2mm）
- 4 个重物（每个约 500g）

**安装方法**：
1. 将 4 根绳子分别绑在无人机 4 个机臂上
2. 绳子长度约 **2 米**
3. 绳子另一端绑在重物上
4. 将重物放在地面，形成"倒金字塔"结构

**作用**：
- 限制无人机活动范围
- 即使失控也只能在 2 米半径内移动
- 防止飞丢

### 7.2 安全检查清单

**在安装螺旋桨前，逐项确认**：

- [ ] 所有传感器已校准（加速度计、罗盘、遥控器）
- [ ] 电调已校准，电机顺序和转向正确
- [ ] 飞控参数已配置（Failsafe 已启用）
- [ ] 代码连接测试和模式切换测试通过
- [ ] 遥控器已开机，信号正常，电量充足
- [ ] 遥控器已设置 RTL/LAND 紧急模式
- [ ] 电池电量 > 80%
- [ ] 螺旋桨安装方向正确（注意正反桨）
- [ ] 螺旋桨紧固，无松动
- [ ] 系留绳索已安装
- [ ] 测试场地空旷，无人员靠近（至少 5 米）
- [ ] 地面平整，无障碍物
- [ ] 天气良好，无风或微风

### 7.3 首次起飞测试

**使用安全飞行脚本**：

```bash
cd /home/linux/drone/drone_gcs
python scripts/safe_flight_test.py \
    --conn /dev/ttyUSB0 \
    --baud 57600 \
    --alt 1.0 \
    --hover 5.0
```

**脚本安全特性**：
1. **高度硬限制**：超过 2.5m 自动降落
2. **心跳监控**：数传断连自动降落
3. **电池监控**：低电压自动返航
4. **Ctrl+C 紧急停止**：按下立即降落
5. **遥控器接管检测**：检测到模式切换立即停止

**测试流程**：

1. **启动脚本**：
   ```bash
   python scripts/safe_flight_test.py --conn /dev/ttyUSB0 --baud 57600 --alt 1.0 --hover 5.0
   ```

2. **脚本会显示安全提示**，按 Enter 继续

3. **观察起飞过程**：
   - 飞控切换到 GUIDED 模式
   - 电机解锁
   - 无人机缓慢上升
   - 到达 1.0m 后悬停

4. **悬停阶段**（5 秒）：
   - 观察无人机是否稳定悬停
   - 观察是否有漂移
   - 脚本会每秒打印状态信息

5. **自动降落**：
   - 悬停结束后自动切换到 LAND 模式
   - 无人机缓慢下降
   - 触地后自动上锁

**如果出现异常**：

| 异常现象 | 紧急操作 | 可能原因 |
|----------|----------|----------|
| 起飞后剧烈晃动 | 立即遥控器切 RTL | 加速度计未校准 |
| 起飞后向一侧漂移 | 立即遥控器切 RTL | 罗盘未校准或干扰 |
| 起飞后快速上升 | 立即遥控器切 RTL | 电调未校准 |
| 起飞后翻滚 | 立即遥控器切 RTL | 电机顺序或转向错误 |
| 代码无响应 | 按 Ctrl+C | 数传通信问题 |
| 数传断连 | 遥控器接管 | 数传距离过远或干扰 |

### 7.4 紧急操作演练

**在首次起飞前，必须演练以下操作**：

1. **遥控器紧急降落**：
   - 将模式开关切到 **RTL** 或 **LAND** 位置
   - 练习 3 次，确保能在 1 秒内完成

2. **遥控器强制上锁**：
   - 油门拉到最低
   - 方向舵（Yaw）打到最右
   - 保持 2 秒
   - **⚠️ 警告**：此操作会导致无人机直接掉落，仅用于极端情况

3. **代码紧急停止**：
   - 按 **Ctrl+C**
   - 脚本会自动执行降落程序

## 阶段八：问题诊断与调优

### 8.1 常见问题

**问题 1：无法解锁（PreArm Check Failed）**

**诊断**：
```bash
python tests/test_connect.py --conn /dev/ttyUSB0 --baud 57600
```
查看 STATUSTEXT 输出，常见错误：
- `PreArm: Compass not calibrated` → 重新校准罗盘
- `PreArm: Accels not calibrated` → 重新校准加速度计
- `PreArm: RC not calibrated` → 重新校准遥控器
- `PreArm: Need 3D Fix` → 等待 GPS 定位（室内无法解决，切换到 STABILIZE 模式）

**问题 2：起飞后漂移**

**可能原因**：
1. 罗盘干扰：远离金属物体、电线
2. 加速度计未校准：重新校准
3. GPS 信号差：室内测试切换到 STABILIZE 模式

**问题 3：代码连接失败**

**诊断步骤**：
1. 检查 WSL 设备：`ls /dev/ttyUSB*`
2. 检查波特率：确保与飞控参数一致
3. 检查数传：LED 应闪烁
4. 检查飞控参数：`SERIALx_PROTOCOL` 和 `SERIALx_BAUD`

**问题 4：心跳超时**

**可能原因**：
1. 数传距离过远（> 100m）
2. 数传功率过低
3. 电磁干扰
4. 波特率不匹配

### 8.2 PID 参数调优（进阶）

**如果悬停稳定性不佳**，可以调整 PID 参数：

在 Mission Planner 的 "Config" → "Extended Tuning" 中：

- **Roll/Pitch Rate P**：增加可提高响应速度，但过大会震荡
- **Roll/Pitch Rate D**：增加可抑制震荡，但过大会噪声
- **Yaw Rate P**：控制偏航响应

**建议**：
- 首次飞行使用默认参数
- 仅在有经验后再调整

## 附录 A：紧急预案总结

### 三级安全屏障

**第一级：代码级保护**
- 高度限制：超过 2.5m 自动降落
- 心跳监控：数传断连自动降落
- 电池监控：低电压自动返航
- Ctrl+C：手动触发紧急降落

**第二级：遥控器接管**
- 切换到 RTL/LAND 模式：立即接管控制
- 优先级高于代码指令
- 响应时间 < 1 秒

**第三级：飞控 Failsafe**
- 遥控器失联：自动 RTL
- 数传失联：自动 RTL
- 低电压：自动 RTL
- 最后一道防线

### 紧急操作优先级

1. **遥控器切 RTL/LAND**（最快，最可靠）
2. **按 Ctrl+C**（代码级紧急停止）
3. **遥控器强制上锁**（仅极端情况，会导致坠落）
4. **断电**（最后手段，会导致坠落）
