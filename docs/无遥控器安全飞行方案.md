# 无遥控器安全飞行方案

最后校准日期：2026-05-16

无遥控器飞行是高风险调试方式。当前代码虽然支持通过地面站 live 模式控制任务，但仍建议优先保留 RC 遥控器或等效人工接管/断电手段。本文只描述在确实无法使用遥控器时的最低安全流程。

## 当前软件保护

- `main.py --mode live --start` 必须额外传入 `--confirm-live-start`。
- FSM 在任务阶段检查飞控连接、heartbeat、外部 RTL/LAND 模式。
- `EMERGENCY` 首次处理会请求 `FlightMode.RTL`。
- MCU 动作有失败响应、超时和最大重试次数。
- mock 模式和视觉 HUD 可在无飞行风险下先验证大部分软件链路。

## 不足

- 软件无法替代人工遥控器的即时姿态接管。
- `arm_and_takeoff()` / `land()` 是阻塞调用，现场异常时仍需物理层面处置。
- 如果数传和电源同时失效，地面站无法继续发出指令。
- 室内环境下 RTL 的实际行为取决于飞控配置，不应盲目信任。

## 最低前置条件

1. 场地清空，有物理隔离或保护网。
2. 有独立断电手段，且操作员站位安全。
3. 电池、电机、电调、桨叶方向、机架固定检查完成。
4. Pixhawk failsafe、LAND/RTL 行为已单独验证。
5. MCU 串口已确认能返回 `RESET_DONE`、`GRAB_DONE`、`RELEASE_DONE`。
6. ESP32-S3 视觉流已用 `run_visual_hud.py` 验证稳定。
7. 默认单元测试通过。

## 推荐流程

1. 跑 mock：

```bash
python main.py --mode mock --start --mock-fast --duration 2 --no-flight-recorder
```

2. 跑视觉 HUD，不解锁飞控：

```bash
python scripts/run_visual_hud.py --duration 20 --draw-targets all --debug-targets selected
```

3. 只验证 live RESET，使用极短时长，并确保现场安全：

```bash
python main.py \
  --mode live \
  --start \
  --confirm-live-start \
  --duration 3 \
  --conn udp:192.168.4.1:14550 \
  --mcu-port /dev/ttyACM0
```

4. 若 RESET、心跳、MCU 串口都稳定，再逐步扩大飞行时间和任务范围。

## 中止条件

出现以下任一情况，停止当天实机任务并回到离线排查：

- 飞控 heartbeat 不稳定。
- MCU 响应缺失、乱码或重复异常。
- 图像流延迟明显堆积。
- active target 与实际任务目标不一致。
- 起飞/降落模式切换不符合预期。
- 现场人员无法明确执行断电或接管动作。
