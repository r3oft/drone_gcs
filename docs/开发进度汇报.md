## 当前重点

1. 飞控实机参数调节。
2. MCU 直连串口实机稳定性验证。
3. pickup/delivery 视觉伺服参数实测。
4. HUD 录像回放与误差/速度曲线复盘。
5. 安全流程固化：live 启动、人工接管、断电和 RTL 策略。

## 近期建议

- 使用 `pytest -q` 作为提交前默认检查。
- 硬件飞测脚本只在人工确认场地和设备后单独运行。
- 每次 live 调试记录完整命令、配置、日志和 HUD 录像。
- MCU 固件需保持文本行协议稳定：命令和响应都以 `\n` 结束。
- 若临时回退 Pixhawk `SERIAL_CONTROL`，必须在记录中写明 `--mcu-transport pixhawk_serial_control`。

## 风险与待确认项

| 项 | 说明 |
|---|---|
| 飞控连接稳定性 | 当前有自动重连参数，但实机行为仍需验证 |
| 起飞/降落阻塞调用 | `arm_and_takeoff()` 与 `land()` 是阻塞式调用，需要现场观察超时和模式切换 |
| MCU 串口权限 | Linux 串口设备权限可能导致 live RESET 阶段失败 |
| 视觉权重 | `weights/` 不入库，调试机必须有正确权重 |
| 文档 PDF | PDF 属于报告素材，不保证与代码逐行同步 |

## 当前推荐命令

```bash
python -m pytest -q
python main.py --mode mock --start --mock-fast --duration 2 --no-flight-recorder
python scripts/run_visual_hud.py --target pickup_zone --draw-targets all --debug-targets selected
```
